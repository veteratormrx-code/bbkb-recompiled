# Поддержка эмодзи

Датасет клавиатуры — **Unicode Emoji 16.0** (пакет `emojibase-data` **16.0.3**). Emoji 17.0 и 18.0 в сетке нет. Русские подписи из `emoji-search.tsv` участвуют в поиске панели. Полный CLDR 49 и шрифт Noto Color Emoji в этой работе не скачивались. Панель эмодзи на устройстве я не открывал и скриншотом не проверял.

## Откуда берётся сетка

`app/package.json` зависит от `emojibase-data` `^16.0.3`. Lockfile фиксирует `16.0.3`. Задача `generateEmojibaseCompact` в `app/build.gradle` читает `node_modules/emojibase-data/en/data.json` и пишет `emoji/emojibase-en.tsv` в каталог сборки. В git этот файл не лежит.

Прочитанный сгенерированный заголовок:

`EBC1	emojibase-data 16.0.3 en/data.json sha256=8cbf636f6b28476065e847360691ca8a6767ed328d3223f9eead4e5c09e61f04`

В `data.json` 1941 запись. Поле `version` не превышает 16. Записей с версией больше 16 нет. Восемь записей версии 16 — это весь набор Emoji 16.0:

| Код | Имя |
| --- | --- |
| U+1FAE9 | face with bags under eyes |
| U+1FAC6 | fingerprint |
| U+1FABE | leafless tree |
| U+1FADC | root vegetable |
| U+1FA89 | harp |
| U+1FA8F | shovel |
| U+1FADF | splatter |
| U+1F1E8 U+1F1F6 | flag: Sark |

`EmojibaseDataProvider` читает компактный файл через `EmojibaseCompactFormat`. На сетку попадает запись, которую `isBaseEmoji` считает базовой и для которой `Paint.hasGlyph` (`canDraw`) отвечает да. Перед проверкой шрифта таких базовых записей 1767. Ответ шрифта кэшируется в `EmojiGlyphCache` (`emojibase-glyphs.bin`). Ключ кэша включает `Build.FINGERPRINT`, SDK и строку идентичности из заголовка файла.

`canDraw` спрашивает глиф всей последовательности. Отдельные части ZWJ или флага не считаются доказательством, что последовательность рисуется. Если в строке есть U+FE0F и целиком она не рисуется, вопрос повторяется без селекторов.

Чего шрифт процесса нарисовать не может, нет ни на вкладке, ни в поиске, ни в попапе тона кожи.

## ZWJ, тон кожи, флаги, недавние

Это уже было в коде до правки поиска.

**ZWJ.** В `data.json` 248 записей содержат U+200D (лицо в облаках, сердце в огне, семья и другие). На сетке остаётся последовательность без пола и без признака «лицом влево/вправо». Таких около 125 до проверки шрифта. Мужские и женские варианты — отдельные записи с `gender`; их 108, `isBaseEmoji` их отбрасывает. Ещё 16 записей с facing left/right, leftward или rightward тоже отбрасываются.

Та же проверка `hexcode.contains("2194")` / `"2195"` убирает качание головой (ZWJ со стрелкой) и заодно сами стрелки ↔ (U+2194) и ↕ (U+2195). Комментарий в коде говорит только про качание головой.

**Тон кожи.** У 323 записей есть массив `skins`, всего 1875 вариантов. У 206 базовых эмодзи есть хотя бы один вариант. Длинное нажатие показывает попап: база и варианты из `getSkinToneVariants`. Выбор запоминает `EmojiToneMemory` в предпочтении `emoji_tone_memory`. Клавиша и слот полоски потом показывают запомненный вариант. Отдельных строк «эмодзи + тон» в поиске нет: ищется база, тон подставляется после.

**Флаги.** Группа emojibase 9 отображается на вкладку `EmojiCategory.FLAGS`. В группе 270 записей, в том числе пары региональных индикаторов (флаги стран). 26 букв regional indicator A–Z на сетку не попадают: у них описание начинается с `regional indicator`.

Белый флаг (U+1F3F3) и чёрный флаг (U+1F3F4) тоже выпадают. Их hexcode — пять символов с префиксом `1F3F`, и `isBaseEmoji` применяет к ним ту же проверку, что к модификаторам тона U+1F3FB–U+1F3FF. Пиратский флаг и радужный флаг длиннее пяти символов, проверка их не задевает.

**Недавние.** `EmojiRecents` хранит `emoji_recent_keys`: JSON-массив, новые сначала, пустые строки — заполнители пустых клавиш. Вкладка недавних — id 0. Оверлей читает не больше 30 (`EmojiCategoryManager.OVERLAY_RECENTS_LIMIT`). Страница фабрики вмещает до 40 (`EmojiKeyboardFactory.RECENTS_MAX_KEYS`). Запись, которую разбор клавиши отвергает, пропускается.

## Чего нет относительно Emoji 18.0

Список сверен с [Emoji Recently Added, v17.0](https://unicode.org/emoji/charts-17.0/emoji-released.html) и [Emoji Recently Added, v18.0](https://www.unicode.org/emoji/charts-18.0/emoji-released.html). В `data.json` этих кодов нет, поэтому панель и поиск их не отдают. Строки про них в `emoji-search.tsv` есть и при поиске не к чему привязываются.

Emoji 17.0:

| Код | Имя в TSV |
| --- | --- |
| U+1FAEA | distorted face |
| U+1FAEF | fight cloud |
| U+1FAC8 | hairy creature |
| U+1FACD | orca |
| U+1F6D8 | landslide |
| U+1FA8A | trombone |
| U+1FA8E | treasure chest |
| U+1F9D1 U+200D U+1FA70 | ballet dancer |

Emoji 18.0, девять новых кодов (плюс десять последовательностей тона кожи для двух больших пальцев; тона в сетку отдельными ключами и так не входят):

| Код | Имя в TSV |
| --- | --- |
| U+1FAEB | cracking face |
| U+1FAF9 | leftwards thumb sign |
| U+1FAFA | rightwards thumb sign |
| U+1FACC | monarch butterfly |
| U+1FADD | pickle |
| U+1F6D9 | lighthouse |
| U+1FA8B | meteor |
| U+1FA8C | eraser |
| U+1FA8D | net with handle |

UTC #181 принял U+1FADD для Unicode 17.0 как APPLE CORE. В таблице Emoji 18.0 и в нашем TSV тот же код назван pickle. В датасете 16.0.3 нет ни того, ни другого.

Emoji 17.0 добавил много ZWJ-последовательностей с тоном кожи для уже существующих людей. Их базы в emojibase 16 есть. Единственная ZWJ-последовательность из TSV, которой в датасете нет, — ballet dancer.

## Русский поиск

Файл `app/src/main/assets/bbmodern/emoji-search.tsv` уже лежал в дереве. Рядом `emoji-search-sources.txt` пишет, что это аннотации CLDR 49 и запасные имена из `emoji-test.txt` Emoji 18.0, скопированные из APK 4pda. В файле 3972 строки. У каждой есть хотя бы одно русское слово. Полное дерево CLDR 49 я не скачивал и побайтно с unicode.org файл не сверял.

Загрузчик `loadRussianAnnotations` и раньше вызывался из `searchData()`, а `searchData()` вызывают и `searchEmojis`, и `topHit`. Русские слова добавляются в алиасы. Слова без кириллицы из TSV не берутся: английское имя, теги и шорткоды уже есть в emojibase.

До правки ключом карты была строка эмодзи как в TSV. У 1615 базовых эмодзи она совпадала с emojibase. У 152 emojibase хранит полностью квалифицированную форму с U+FE0F, а TSV — без него (👍, ✋, 😐, семья и другие). Поиск эти русские слова не видел. Совпадений «в TSV есть FE0F, в emojibase нет» среди базовых не было.

Сейчас `annotationsFor` при промахе повторяет запрос без U+FE0F. Если в строке TSV селектор всё же есть, то же слово записывается и на ключ без него, не затирая уже занятый ключ. Короткое русское имя из второго столбца остаётся одной фразой, когда в нём нет латинских букв и цифр: запрос `большой палец вверх` совпадает целиком. Имя вроде `значок SOS` целиком не берётся, иначе латинский кусок ловил бы запрос `s`. Отдельные слова по-прежнему режутся по пробелу и `|`. Английский кусок при этом отбрасывается.

Шкала та же: точный алиас даёт 30, вхождение — 5. Порог полоски подсказок `STRIP_MIN_RELEVANCE` равен 40 и по-прежнему требует точное или префиксное совпадение английского описания или тега. Запрос из одних русских слов до полоски не доходит: `topHit("лайк", 40)` пустой, `topHit("лайк", 30)` возвращает 👍. Панель эмодзи берёт любое совпадение с оценкой больше нуля, не больше 80.

2040 строк TSV — варианты с тоном кожи. В индекс поиска они не входят.

Проверка: `EmojiRussianSearchTest` и `EmojibaseTopHitIndexTest` прошли `:app:testDebugUnitTest`. Датасет в тесте русского поиска помечен рисуемым целиком, без `Paint.hasGlyph`. `лайк` и фраза `большой палец вверх` находят 👍 с U+FE0F. `все равно` находит 😐 с U+FE0F. `улыбка` находит 😀. `трескается` (Emoji 18.0, cracking face) не находит ничего. Ссылка полного перебора в индексе — `indexedScore`, с теми же русскими алиасами.

## Почему шрифт Noto в APK не кладётся

Рисование идёт системным шрифтом процесса: `Paint.hasGlyph`, без своего `Typeface` и без файла COLR/CBDT в ассетах. На Android 17 эмодзи уже рисует системный шрифт. Отдельный Noto Color Emoji — это больше 10 МБ в APK. Клавиатура им могла бы нарисовать глиф только у себя и только если начать подставлять этот `Typeface` в свои `Paint`. Поле чужого приложения всё равно рисует вставленные коды своим системным шрифтом. Глифа, которого нет в системе, у получателя не появится. Текущий фильтр как раз скрывает то, что системный шрифт не рисует, так что приватный шрифт в IME разошёлся бы с тем, что увидит пользователь в тексте.

Файл шрифта не скачивался.

## Что не проверялось на устройстве

Юнит-тесты гоняют разбор датасета и поиск. Под Robolectric `Paint.hasGlyph` в обычном пути загрузки ложен (`EmojiTestEnv`), поэтому тест русского поиска не доказывает, что глиф виден на экране. Вкладку эмодзи, попап тона, флаги, недавние и поиск в живой клавиатуре я не открывал и не снимал.
